# ADB/Fastboot Wrapper

Прозрачный враппер для `adb.exe` и `fastboot.exe`, который логирует все вызовы, аргументы, переменные окружения и код завершения. Помогает отлаживать проблемы с Android-инструментами, особенно в средах, где `adb` запускается из графических приложений.

## Особенности

- 📝 Полное логирование каждого вызова: время, PID, рабочий каталог, командная строка (сырая и разобранная), дескрипторы STDIN/STDOUT/STDERR.
- 🔄 Прозрачная передача управления реальному `adb` или `fastboot` (переименованные в `*.real.exe`).
- 🖥️ Корректно работает как из консоли, так и из GUI-приложений (автоматически определяет наличие консоли и не создаёт лишних окон).
- 📁 Лог записывается в файл `adb_trace.log` в папке враппера.
- 🛠️ Сборка через MSVC (Visual Studio) с помощью простого PowerShell-скрипта.
- 🔄 Поддержка непрерывной интеграции (GitHub Actions) — автоматическая сборка `wrapper.exe`.

## Сборка

### Требования

- Windows с установленной **Visual Studio 2022** (или более новой) с компонентом "Разработка классических приложений на C++".
- Откройте **Developer PowerShell for VS 2022** (или любой терминал, где доступен `cl.exe`).

### Инструкция

1. Склонируйте репозиторий:
   ```bash
   git clone https://github.com/yourusername/adb-wrapper.git
   cd adb-wrapper

2. Запустите скрипт сборки:
   ```bash
   powershell
   .\build.ps1
   ```

- Скрипт:

 - Проверяет наличие компилятора cl.exe.

 - Удаляет старые объектные файлы и wrapper.exe.

 - Компилирует wrapper.cpp в wrapper.exe с флагами /std:c++17 /EHsc /W4 /DUNICODE.

 - В результате в папке появится wrapper.exe.

### Установка

- Чтобы враппер перехватывал вызовы adb и fastboot:

 - Переименуйте оригинальные исполняемые файлы:

 - adb.exe → adb.real.exe

 - fastboot.exe → fastboot.real.exe

 - (они должны лежать в той же папке, где будет враппер).

 - Скопируйте wrapper.exe в ту же папку и переименуйте его в:

 - adb.exe (для перехвата adb)

 - fastboot.exe (для перехвата fastboot)

 - Можно создать жёсткие ссылки или копии — враппер определяет своё имя и выбирает соответствующий реальный исполняемый файл.

- Убедитесь, что папка с враппером находится в PATH или используется прямой путь.

- Теперь любой вызов adb или fastboot будет проходить через враппер, а логи будут писаться в adb_trace.log.

### Использование

- Враппер не требует дополнительных параметров. Все аргументы, переданные ему, прозрачно передаются реальному adb/fastboot. Код завершения враппера в точности равен коду завершения дочернего процесса.
